# Автоматический выбор Ruflo

Применяй по смыслу задачи без явного упоминания Ruflo пользователем. Сначала соблюдай AGENTS.md и docs/RUFLO_INTEGRATION.md.

1. Классифицируй задачу: простая / средняя / сложная / критическая. Для простой либо последовательной задачи не запускай рой.
2. Для сложной/критической задачи с независимыми результатами проверь наличие Ruflo MCP в текущем сеансе, реально доступные инструменты, действующий безопасный smoke test, права и бюджет. Регистрация не равна работающему серверу. Если есть подходящий read-only health/status вызов, проверь его. Не придумывай имена и параметры инструментов.
3. Если условия выполнены, автоматически используй доступные инструменты Ruflo для координации. По умолчанию максимум два рабочих агента; у каждого конкретная цель, файлы, критерий приёмки. Не допускай пересекающихся записей. Отличай регистрацию роли от реального исполнения агентом. Не запускать иных платных моделей и не передавать секреты или клиентские данные. Не создавать background workers.
4. Если Ruflo недоступен или не даёт пользы, продолжай безопасным штатным способом; укажи конкретное ограничение. Не устанавливай непроверенные пакеты, не меняй настройки доступа или лимиты автоматически.
5. Применяй Superpowers для плана, тестов и ревью, Codebase Memory для навигации, Composio для разрешённых внешних операций. Главный агент проверяет итог по исходникам, diff и тестам; не доверяй только отчётам рабочих агентов.
6. В итоговом отчёте сложной задачи укажи: решение об использовании Ruflo, реальные MCP вызовы (без секретов), фактически выполненные подзадачи, проверки и ограничения. Фиксируй подтверждённые результаты в PR в пределах разрешений.

Никаких автоматических merge, deploy, новых расходов и клиентских данных. Правило включения Ruflo не расширяет полномочия пользователя.
