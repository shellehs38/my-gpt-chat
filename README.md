# Строительный помощник «СВОИ ЛЮДИ»

Личный помощник для фасадных работ, смет, документов и организации строительного бизнеса. Next.js, React и серверное подключение OpenAI Responses API. Подписка ChatGPT не заменяет API-ключ и оплату API.

## Запуск

Нужен Node.js 22 или новее.

1. Выполнить `npm ci`.
2. Скопировать `.env.example` в `.env.local` и заполнить серверные настройки.
3. Выполнить `npm run dev`, открыть `http://localhost:3000` и войти с настроенным паролем.

Для производственного запуска: `npm run build`, затем `npm start`.

## Доступ и секреты

- `OPENAI_API_KEY` — серверный ключ модели; `OPENAI_MODEL` позволяет изменить модель без редактирования кода.
- `ASSISTANT_ACCESS_PASSWORD` — уникальный пароль владельца, не короче 12 символов.
- `ASSISTANT_SESSION_SECRET` — независимый случайный секрет, не короче 32 байтов. Команда генерации приведена в `.env.example`.
- `ASSISTANT_PUBLIC_ORIGIN` — необязательный точный публичный адрес вида `https://your-assistant.example`, если обратный прокси меняет схему или Host. Подменённые forwarded-host заголовки не используются для разрешения записи.
- На Vercel эти настройки добавляются как переменные окружения выбранного проекта. После изменения настроек нужна новая публикация.
- Пароли, ключи и заполненные env-файлы не передаются в GitHub, браузерный код и журнал запросов. Без корректной настройки доступа API закрыт.
- Сессия хранится в подписанном HttpOnly cookie и действует 12 часов. В production cookie передаётся только по HTTPS. Смена пароля или секрета делает старые сессии недействительными. Сохранённый в браузере проект, его импорт, экспорт и удаление доступны в интерфейсе только после входа.
- Ограничены частота входа, запросов и число параллельных обращений к модели. Встроенные счётчики работают на экземпляр процесса: для нескольких serverless-экземпляров и общего бюджета нужны общие лимиты на стороне хостинга/провайдера. Сам по себе локальный счётчик не является глобальным финансовым лимитом.

## Сметы и сохранение

Позиции, варианты и таблицы имеют отдельные идентификаторы. Количество, единицы и цены видны на компьютере и телефоне. Суммы рассчитываются детерминированно с округлением до копеек; неизвестная цена не заменяется нулём. Если данных не хватает, показывается известный подытог, а не подтверждённый полный итог. После ручной правки экран, следующий запрос, Markdown и HTML используют одну текущую структуру; старые текстовые формулы и итоги ответа модели не остаются действующими.

Редактирование, копирование и экспорт используют одни текущие данные. История разговора и версии сначала сохраняются **в текущем браузере**. После подключения Google Drive помощник ведёт неизменяемую облачную историю и позволяет восстановить проект на другом устройстве; точный статус записи показывается в интерфейсе. Ручной JSON-экспорт остаётся резервным способом переноса. Обычный выход сохраняет проект для следующего входа; кнопка «Выйти и удалить локальные данные» завершает сессию и очищает локальную копию вместе с незавершённой командой учёта текущей вкладки, но не удаляет историю Drive. На общем компьютере используйте именно этот вариант после предварительного экспорта нужных данных.

Обычные последующие вопросы передают ограниченную историю разговора; последние изменения сметы учитываются в контексте. При ошибке запроса предыдущий результат сохраняется. Незавершённый ответ модели не считается готовой сметой.

ИИ не заменяет обмеры, проект, техкарты производителя или согласование цены. Неизвестные сведения остаются открытыми вопросами. Несущая способность, пожарная безопасность и обязательные нормативные требования требуют профильной проверки.

## База строительных знаний

Версионируемый источник правил для плагина ChatGPT находится в
[`plugin-source/svoi-lyudi-builder`](plugin-source/svoi-lyudi-builder). В него
входят отдельные справочники по фасадам, основным строительным операциям,
сметному и финансовому контролю, качеству, безопасности, складу и логистике.
Карта нормативных источников содержит дату сверки реквизитов и требует проверки
действующей редакции перед точной ссылкой на пункт. При запуске и сборке
`npm run knowledge:export` создаёт серверный снимок тех же пяти справочников.
GPT-чат сайта выбирает до трёх разделов по текущей задаче; короткое продолжение
учитывает последние вопросы пользователя. В браузер справочники и внутренние
инструкции не передаются. Общие обязательные правила дополнительно публикуются
в снимке Codebase Memory.

## Клиенты и расходы на сайте

В разделе «Бизнес и продажи» работает отдельный серверный учёт. Это не текстовая смета: клиент, объект и каждое движение расходов читаются и записываются в выбранную Google Таблицу. Подключённый к ChatGPT Google Drive не даёт этому сайту доступ автоматически.

Для запуска нужны серверные настройки:

- `GOOGLE_SERVICE_ACCOUNT_JSON` — JSON-ключ отдельного сервисного аккаунта Google, сохранённый как Secret/Sensitive только в Production Vercel. Его содержимое не отправляют в чат и не коммитят.
- `GOOGLE_SHEETS_SPREADSHEET_ID` — необязательный ID книги. По умолчанию используется подтверждённая база `1-frD3ABf1G-IH1cd31Fktb9NY2XPLg05VGLOwSsgA2U`.

Порядок подключения:

1. В Google Cloud выбрать или создать проект и включить Google Sheets API.
2. В IAM → Service Accounts создать отдельный аккаунт сайта. Проектные роли для доступа к конкретной таблице ему не требуются.
3. В аккаунте открыть Keys → Add key → Create new key → JSON. Файл с закрытым ключом хранить как секрет.
4. Открыть нужную Google Таблицу и предоставить роль «Редактор» только адресу `client_email` из JSON. Публичный доступ не включать.
5. В настройках проекта Vercel добавить весь JSON в `GOOGLE_SERVICE_ACCOUNT_JSON`, окружение Production, тип Secret/Sensitive. Выполнить новую публикацию.
6. Войти на сайт, выбрать «Бизнес и продажи» и проверить подключение. До успешного доступа и проверки схемы сайт не объявляет учёт готовым и не выполняет платные команды модели для неподключённой базы.

Рабочая схема: «Клиенты» A:F, «Лист1» A:P, «Расходы» A:H. Скрытый лист `_ВебОперации` A:E хранит идентификаторы команд, их хэши и подтверждённые результаты для восстановления после сетевой ошибки. Исходная вкладка сохранена в резерве. ФИО, телефоны и описания передаются в Sheets как текст, без выполнения пользовательских формул. Цена договора, фактические расходы и полученные оплаты не подменяют друг друга; неподтверждённый налог не назначается.

Пример учебного сценария после подключения:

1. «Сохрани тестового клиента Тестов Иван Сергеевич, телефон +7 (000) 000-00-01 — нерабочий. Объект ДЕМО-1, Учебный адрес 1, отделка фасада 100 м², цена клиенту 100000 рублей. Учебная запись, налог неизвестен».
2. «Тестов» — однозначный объект выбирается автоматически; однофамильцы и несколько объектов требуют выбора.
3. «Внеси расходы: материалы 12000 рублей, доставка 2000 рублей» — две строки, учтённые расходы 14000 рублей.
4. «Добавь ещё расход: работа 3000 рублей» — три строки, расходы 17000 рублей, предварительная разница цены и внесённых расходов 83000 рублей.

Сетевой повтор использует тот же UUID команды; новая реальная трата получает новый UUID. Незавершённая команда сохраняется в sessionStorage текущей вкладки, после обновления предлагается ручная проверка с прежним ключом. Одновременные записи защищаются атомарным пакетом Sheets с маркером операции. Постоянный журнал операций не очищается; удалять старые служебные маркеры можно только после проверенной записи журнала и истечения защитного интервала. Верификация механизмов на тестовых вкладках не равна проверке подключения сервисного аккаунта: реальная запись сайта проверяется отдельно после настройки доступа.

## Память кода для разработки

Подключение Codebase Memory MCP, проектная конфигурация Codex и воспроизводимые команды описаны в [docs/CODEBASE_MEMORY.md](docs/CODEBASE_MEMORY.md). Архитектурные решения и постоянное правило логотипа хранятся в [ADR](docs/CODEBASE_MEMORY_ADR.md) и обновляют локальную память при индексации. При сборке нативный движок также создаёт снимок публичной памяти: GPT-чат сайта получает его в каждом запросе, а плагин ChatGPT читает тот же снимок через MCP `/api/mcp` (четыре инструмента чтения). Ревизия и отпечаток показывают версию; переписка и данные клиентов туда не записываются.

Серверный помощник получает подходящие карточки материалов из того же источника. Порядок обновления, правила расчёта, перенос старых объектов и проверки: [docs/FACADE_CALCULATOR.md](docs/FACADE_CALCULATOR.md).
