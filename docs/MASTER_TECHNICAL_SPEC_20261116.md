# Мастер-ТЗ: завершение технических задач и интеграций «СВОИ ЛЮДИ»

**Версия:** 1.0 от 16.11.2026. **Исполнители:** Codex (код и тесты), ChatGPT Work (проверки, анализ, координация через доступные инструменты). **Владелец решения:** руководитель ООО «СВОИ ЛЮДИ». **Статус:** техническое задание, а не разрешение на релиз/расходы/передачу данных.

## 1. Цель и границы

Довести существующую цифровую систему компании до проверяемого состояния: GitHub как источник правил, Codex/Work как исполнители, основной сайт и Telegram-ассистент как интерфейсы, надёжная маршрутизация моделей, сохранная история и учёт, обработка строительных файлов, автоматизация заявок, тестирование и резервирование. Не создавать дубликаты уже работающих систем только ради формального «подключено 13 репозиториев».

**Целевой результат:** по каждой задаче есть владелец, решение, конкретный артефакт, прямые ссылки на PR/commit/тесты и статус DONE / VERIFIED / BLOCKED / NOT_APPLICABLE. DONE допустимо только после реального теста. «Репозиторий добавлен», «библиотека установилась в CI», «контейнер Online» не равны работающей интеграции.

**Строгие ограничения:** не изменять Production, платные тарифы, реальные данные, ключи, Google Sheets, рабочую маршрутизацию и публичные домены без отдельного конкретного подтверждения владельца. Внешние провайдеры не получают клиентов, телефоны, сметы и личные диалоги до проверки условий/разрешений. Никогда не переносить пароли/ключи в код, GitHub Issues, скриншоты, PR или логи.

## 5. Поперечные инженерные требования

**Архитектура:** API-контракты версионированы; команды с денежными последствиями идемпотентны; обратная совместимость клиентских данных и экспортов; минимальные права интеграций; все фоновые процессы имеют bounded retries, таймаут и dead-letter/audit. Отдельные staging/production конфиги; скрипты не должны самопроизвольно запускать новые сервисы.

**Безопасность:** секреты только в утверждённых vault/env, rotate по процедуре, нет ключей в логах/артефактах/LLM промптах. PII и клиентские документы не используются в тестах; ограничения на форматы файлов, размер, SSRF, вредоносные документы/макросы и исполнение кода. Проверить угрозы Prompt Injection в GitHub README, PDF, веб-страницах и MCP.

**Строительная корректность:** работа и материалы раздельно, неизвестные цены не заменять нулём, не прибавлять автоматическую старую надбавку 40%, зарплату директора и прибыль считать отдельными статьями согласно утверждённой смете. Не выдавать неподтверждённые СП/ГОСТ, размерность, инженерные выводы и расчёты несущей способности. Фирменные оригинальные PNG и полупрозрачный водяной знак на каждой странице клиентских документов.

**Наблюдаемость:** health, реальные synthetic probes, latency p50/p95, error rate, токены/стоимость, диск/бэкап, логирование по correlation-id без чувствительных данных. Проверять отказы зависимостей и возврат к предыдущей версии.

1. Начни с P0, не повторяй уже подтверждённые тесты без причины. Результаты GitHub считать достаточными только при совпадении commit SHA и сценария.
2. Каждый этап — отдельный PR и запись в issue; маленькие атомарные изменения, без массового объединения 13 платформ.
3. После задачи обновляй docs/AI_INTEGRATION_STATUS_20261105.md (или новый журнал с обратной ссылкой), docs/CODEX_WORK_SHARED_CONTEXT.md, tools/integrations/catalog.json и AGENTS.md только при изменении устойчивого правила.

5. Если доступов или финансового разрешения нет, полностью закончи доступную часть, подготовь код/Preview/тесты и обозначь один конкретный блокер без требования прислать секреты в чат.
6. Нельзя самостоятельно объявлять новые тарифы, полное подключение ChatGPT Work к внешним моделям, рабочее резервирование или успешный Production без отдельного факта.
