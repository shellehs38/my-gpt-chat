# Регламент применения установленных плагинов

Дата утверждения владельцем: 2026-11-02.
Область действия: задачи ООО «СВОИ ЛЮДИ» и работа над ИИ-помощником. Это инструкция для агентов и исполнителей, читающих репозиторий, а не автоматическое подключение плагинов к сайту.

## Основное требование

1. Перед выполнением задачи определять, какие уже установленные и доступные плагины/коннекторы подходят для неё. Предпочитать прямые действия через них ручным инструкциям, когда права и функции позволяют.
2. Использовать каждый плагин **по его назначению, отдельно**, с собственными результатами и проверкой ошибок. При необходимости сочетать несколько плагинов в одной задаче, не подменяя данные одного сервиса догадками о другом.
3. Не запускать все установленные плагины на каждом запросе: нерелевантные вызовы бесполезны, замедляют работу, могут увеличить стоимость и расширить доступ к данным без необходимости.
4. Когда подключение недоступно, не завершено или прав недостаточно, сообщать точное ограничение; не утверждать, что операция выполнена.
5. Использовать только реально доступные в текущей среде действия. Периодически сверять доступные плагины по фактическому каталогу, а не предполагать постоянство списка.
6. Давать прямые ссылки на проверенные результаты: репозиторий, PR, документ, проект или опубликованный сайт.

## Роли инструментов (неисчерпывающие примеры)

| Направление | Подходящие подключённые инструменты | Правило использования |
| --- | --- | --- |
| Код, репозитории, задачи разработки | GitHub; Graphify / Codebase Memory при наличии | Изучать фактические исходники, ветки и PR; не утверждать состояние без чтения |
| Сайт, релизы, диагностика | Vercel | Сначала проверки; публикации и изменения Production только по отдельному разрешению |
| Поиск материалов, цен, поставщиков, конкурентов | Firecrawl; другие доступные инструменты поиска | Проверять регион, дату, источник, отделять оценочные данные от подтверждённых |
| Клиенты, объекты, сметы и финансы компании | Google Drive / Sheets, Airtable, Supabase — по фактическому источнику данных | Не смешивать базы; проверять систему-источник и права; не менять учёт без обоснованного поручения |
| Реклама, карточки товаров, графика | Canva, Figma, Adobe — при доступности | Оригинальные утверждённые логотипы; проверять исходник и ссылку на результат |
| Почта, встречи, задачи | Gmail, Google Calendar, Notion и другие доступные | Перед действиями проверять адресата, дату и разрешения; сообщать о результате |
| Чат-боты и автоматизации | Подходящие подключённые инструменты конкретного проекта | Выбирать по задаче клиента; отдельные интеграции и явная проверка передачи данных |

## Границы доступа и безопасность

- **Установка плагина в ChatGPT не означает его автоматическое подключение к приложению в GitHub или на Vercel.** Для веб-приложения требуются отдельные API, разрешения, серверные интеграции и проверка.
- Не раскрывать и не коммитить API-ключи, токены, пароли, клиентские персональные данные и содержимое секретов.
- Не изменять Production, секреты, рабочие таблицы и действующие сервисы без соответствующего разрешения. Для предложений по коду предпочитать отдельную ветку и pull request.
- Учитывать требования сервиса к подтверждению отправки писем, публикаций, финансовых операций и других существенных действий.
- Не заявлять о постоянном фоновом выполнении задач одним лишь фактом наличия плагинов: требуется действующая автоматизация или отдельная инфраструктура.
- Приоритет: безопасность, ограничения пользователя, достоверность и проверяемый результат. Если инструмент не подходит, не применять его формально ради требования «все плагины».

## Пример правильной последовательности

Задача: «Обновить на сайте помощника исследование цен на фасадные материалы».

1. Прочитать правила и код в GitHub, определить затронутые модули.
2. Через доступный инструмент поиска/Firecrawl собрать актуальные материалы, цены и поставщиков, пометить регион и дату.
3. Подготовить изменения в отдельной ветке и PR; проверить тесты.
4. До отдельного разрешения владельца не публиковать изменения в Vercel Production.
5. Дать прямые ссылки на фактические результаты и явно назвать непроверенные части.
