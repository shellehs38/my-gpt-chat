- API-ключ читается из серверной переменной окружения, не из клиентского кода.

## Ограничения текущей реализации

- Чат не сохраняет историю в базе данных.
- Нет авторизации пользователей и разграничения доступа к проектам.
- Нет отдельного детерминированного расчётного модуля и тестов сметной арифметики.
- Нет подключённого поиска по строительным документам и источникам.
- Нет загрузки файлов в приложении.
- Нет реестра клиентов, заявок, объектов, закупок и финансов по проектам.
- Нет явно настроенного тестового набора и CI-проверки типов/тестов в GitHub Actions.
- Ограничение размера тела запроса опирается на заголовок `Content-Length`; требуется усилить проверку фактически прочитанного тела.
- Ограничения частоты запросов нужно проектировать с учётом нескольких серверных экземпляров, а не только памяти одного процесса.
- В режиме документов пока нет полноценного механизма шаблонов, версий и экспорта файлов.

## Правила выпуска

- Не объединять изменения в `main` и не переключать production без отдельного подтверждения пользователя.
- У каждого этапа должны быть код, документация, проверка и запись в журнале работ.
- Статус `success` сборки не означает, что все функции проверены вручную.
- Для несущих конструкций и иных высокорисковых решений приложение не заменяет инженерный расчёт и проверку специалистом.
