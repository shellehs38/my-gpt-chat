# Harness² / опыт задач — пилот в изолированной ветке

## Что сделано
- Утверждённые уроки из `data/agent-lessons.json` выбираются по теме нового запроса.
- Для включения в Preview необходимо установить `AGENT_EXPERIENCE_ENABLED=1`. По умолчанию **выключено**. Production не изменён.
- Память добавляется **в инструкции вокруг модели**, параметр `OPENAI_MODEL` не меняется.
- Исходные диалоги, имена клиентов, телефоны, адреса и ключи не сохраняются.
- Уроки со статусом `candidate` никогда не попадают в контекст; добавить `approved` можно только через проверенный коммит/PR.
- Память ограничена четырьмя релевантными уроками на запрос; ранее подтверждённые цифры нельзя применять к новым объектам без основания.

## Что ещё не сделано
Это **первый шаг интеграции**, а не полноценный Harness² в работающем чате. Пока задачи не создают уроки автоматически: хранилище статично до коммита. Механизмы Propose–Probe–Compose, автоматическая обратная связь и долговременная запись кандидатов в отдельную БД отсутствуют.
Чтобы накопление стало автоматическим, нужен изолированный worker, отдельное надёжное хранилище, проверка фактов и контролируемое одобрение изменений. Не записывайте raw chat или клиентские данные в публичный GitHub.

## Harness²: изолированная проверка официального проекта
Источник: https://github.com/google-research/harness2
Проверенный upstream-коммит: `6868817518876de8fd170c6a8354daca273b6191`

- Отдельный Python 3.12 runner под Linux, не Vercel API.
- Сначала запускать только `harness2-demo` без ключей модели, в изолированном окружении.
- Для model-backed испытаний понадобятся отдельные креденшелы, расход API и ограничения на сеть. Публичный Harness² предупреждает, что executor может запускаться с отключённой песочницей. Не выдавать ему Production-секреты, доступ к клиентской БД или права записи в main.
- Исходный модельный API `OPENAI_MODEL` не менять.
- Изолированный GitHub Actions workflow запускается только вручную и не требует секретов; его результаты не применяются к приложению.

## Следующие шаги до выпуска
1. Проверить CI/TypeScript и ручной демонстрационный запуск Harness².
2. Создать приватное хранилище уроков и кандидатов; тестовая среда должна быть отделена от Production.
3. После завершения задачи: сформировать минимальный обобщённый урок, удалить PII, проверить факты и источник, оставить `candidate`.
4. Прогнать регрессионные тесты на сметах/логотипах/площадях и измерить качество ответа до/после. Применять улучшение только при доказанном результате и с возможностью отката.
5. После одобрения владельца включить функцию в Preview, затем отдельно согласовать Production.
