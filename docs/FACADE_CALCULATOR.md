# Калькулятор и знания о фасадных материалах

Полный калькулятор хранится в `public/facade-calculator`, открывается по адресу
`/facade-calculator/` и доступен из вкладок «Фасады» и «Смета и расчёты».
Исходная версия и хеши перенесённых файлов: `docs/CALCULATOR_SOURCE.json`.
Проекты павильона, цены конкретных объектов, переписка и данные клиентов сюда
не включены. Оригинальный PNG сохранён без изменений.

## Один каталог для интерфейса и помощника

Источник материалов — `public/facade-calculator/material-catalog.mjs`.
Он содержит 10 семейств металлической облицовки, варианты Grand Line,
«Металл Профиль», STYNERGY и «БАЙКОМ», пользовательские профили и шесть карточек
утеплителей с ограничениями применения. Размеры, заводской вариант, направление
монтажа, комплектующие, источники и дата проверки сохраняются отдельно.

`npm run catalog:export` создаёт из него:

- `data/facade-material-catalog.json` для серверного контекста;
- `public/facade-calculator/catalog.json` для чтения другими помощниками;
- `public/facade-calculator/materials-guide.md` с карточками и инструкциями.

Серверный модуль `lib/server/facade-catalog.ts` добавляет только относящиеся к
вопросу карточки в инструкции OpenAI через `buildInstructions`. Каталог не
добавляется целиком к каждому запросу и не меняет назначение остальных вкладок.
Новый вопрос о фундаменте или кровле имеет приоритет над прошлой фасадной темой.
Это подключение справочных данных к ответам; веса модели не переобучаются.
Серверный чат не вызывает браузерный движок калькулятора и не должен утверждать,
что выполнил такой вызов или сохранил проект, если этого не произошло.

## Правила расчёта

Количество панелей предварительное: чистая площадь делится на полезную ширину
и заказную длину, затем учитываются запас, закреплённые остатки/заказы и упаковка.
Цена такой панели задаётся за штуку указанной длины. Раскладка и раскрой нужны
отдельно. У открытого планкена рабочий модуль с зазором отличается от физической
ширины рейки.

Подсистема по прямоугольным стенам — предварительная сетка по габариту, без вычета
проёмов. Шаги и крепёж берутся из проекта; усиления, стыки и обрамления добавляют
по раскладке. Сложные поверхности требуют своих объёмов. Откосы и отливы имеют
свои замеры и появляются в составе при добавлении первого проёма нужного типа.

Утеплители выбираются отдельно по слоям: внутренний, наружный или единственный.
Два слоя считают раздельно, со смещением стыков. Роль материала не подтверждает
совместимость всей системы. XPS из карточки локальных узлов не подставляется
автоматически на весь навесной фасад. Цены и неподтверждённые нормы не назначаются.
Запас материалов и округление упаковок не увеличивают объём труда.

## Сохранение и перенос

Калькулятор хранит свои объекты и версии в IndexedDB данного браузера.
Это отдельное хранилище от диалога и Google Drive помощника. Новый адрес имеет
другой origin, чем прежний Sites-калькулятор: для переноса нужно сохранить JSON
на прежнем адресе и импортировать его через «Файл проекта» на новом.
Прежний адрес сохранён в интерфейсе для доступа к старым объектам.

Просмотр каталога не меняет смету. Применение комплекта выполняется отдельной
кнопкой. Для заполненной вручную сметы доступен отдельный расчёт по тем же замерам.
Смена профиля или длины панели сбрасывает её прежнюю цену и остатки.

## Проверка обновлений

После изменения источника запустить `npm run catalog:export`,
`npm run typecheck`, `npm test`, `npm run test:calculator` и `npm run build`.
Сборка также обновляет архитектурную память. Приватные контрольные сметы не
публикуются; при необходимости их можно проверить локально через
`FACADE_PRIVATE_PAVILION_FIXTURE`. Пропуски этих проверок без файла отмечаются явно.

При обновлении перенесённой версии калькулятора проверить происхождение файлов
и обновить `docs/CALCULATOR_SOURCE.json`. Параметры конкретного заказа сверять с
актуальными документами производителя: дата проверки каталога не подтверждает
неизменность всех документов на день нового вопроса.
