## Контекст и что уже существует

Проект: [shellehs38/my-gpt-chat](https://github.com/shellehs38/my-gpt-chat), Next.js/React/TypeScript. Есть `AGENTS.md`, `@modelcontextprotocol/sdk`, экспорт PDF/DOCX/XLSX, маршрутизатор FreeLLMAPI/OmniRoute и Codebase Memory (индекс кода). Telegram-помощник на Railway разрабатывается отдельно; Google Sheets уже используется для учёта. Установка ещё одного чат-интерфейса или маршрутизатора без реальной причины дублирует текущую инфраструктуру.

## Рекомендуемая последовательность интеграции

### 1. Playwright — контроль качества существующего сайта

Сначала выявить причины проблем релизов Vercel и настроить UI-тесты **после успешной публикации Preview**: авторизация на синтетических данных, сметы, переключение режима помощника, экспорт документа с PNG и водяным знаком, проверка пустых/неизвестных цен. Playwright не исправляет Vercel `Resource provisioning failed` — это самостоятельная инфраструктурная проблема.

**Критерий успеха:** тесты выполняются по Preview и на изменениях PR; отчёт без логинов и клиентских данных. Не запускать опасные сценарии на реальном Production.

### 2. MarkItDown vs Docling — чтение строительных файлов

Не ставить оба в основной Next.js сервер без анализа ресурсов. Создать отдельный Python-процесс/воркер в тестовой среде. Проверить на наборе из ≥10 искусственных файлов: простые PDF, многостраничные таблицы, DOCX, прайсы Excel, сканы, чертежи. Сравнить долю извлечённых позиций/чисел, структуру таблиц, время и объём RAM. **Распознавание линий/размеров на чертеже не доказывает правильность технического проекта.** Нужна независимая верификация размеров и инженерных решений.

MarkItDown удобен для извлечения текста и структуры; OCR для изображений/сканов может требовать отдельного плагина и LLM Vision, что способно передавать данные внешнему провайдеру. Docling предназначен в том числе для сложной структуры PDF и OCR, но его вычислительные требования нужно замерить. Устанавливать Python-зависимости отдельно от Next.js.

### 3. Mem0 — долговременная память рабочего помощника

Нынешний Codebase Memory индексирует **структуру кода**, не расходы и диалоги клиентов. Mem0 решает другую задачу: выборочная долговременная память приложения с метаданными и контролем доступа. Не выдавать его за персональную память ChatGPT, Work или Codex Cloud.

Прототипировать с **вымышленными** данными и строгими scope `company_id/user_id/project_id`, возможностью корректировки/удаления, журналом извлечения, запретом межклиентских утечек. После проверки конфиденциальности и условий хранения данных можно обсуждать использование с реальными объектами. Сначала проверить, можно ли решить ту же задачу текущими Supabase/Google Sheets без нового сервиса.

### 4. n8n — автоматизация бизнес-процессов

Развернуть **только отдельно и после оценки бюджета/прав**, первый сценарий на тестовых данных: заявка из разрешённого источника → запись в тестовую Sheets/CRM → уведомление Telegram → напоминание ответственному. Обязательны идемпотентность (одна заявка не создаёт десять дублей), аудит, повтор при временном сбое, резервные копии, ограничение прав. **Не обещать интеграцию с Авито через несуществующий или неразрешённый API**.

n8n — **fair-code, не OSI-open-source**. По FAQ n8n от 06.10.2026, бесплатная Community при собственном размещении подходит для внутренних workflows, которые редактируют сотрудники компании; предоставление клиентам возможностей создавать/редактировать workflows требует коммерческой лицензии. Условия проверить перед использованием для сторонних клиентов: https://support.n8n.io/article/can-i-use-your-license-for-my-use-case .

### 5. Skills для Codex и CRM — после проверки первых четырёх

[obra/superpowers](https://github.com/obra/superpowers) изучить как источник конкретных навыков тестирования/планирования. Не выполнять команды установки и не загружать непроверенные agent instructions в общий Codex без кода-ревью: правила компании и безопасность имеют приоритет. 

[Twenty](https://github.com/twentyhq/twenty) протестировать на 10–20 синтетических лидах с раздельными воронками «фасад / строительство / инженерные работы», задачами по звонкам и владельцем сделки. Google Sheets не переносить, пока не протестированы экспорт, дубли, права, бэкапы и миграция.

## Как использовать этот документ

- Codex/Work: сначала `AGENTS.md`, затем этот список кандидатов.
- **Ничего из списка не считать установленным/подключённым** до записи реального теста с commit/PR и результатом.
- Выбирать одну интеграцию за этап. Не разворачивать Dify + n8n + Mem0 + CRM в Production «на всякий случай».
- Без самостоятельного согласования не менять Railway/Vercel Production, Gemini/Groq ключи, платные тарифы, клиентские данные и существующий Google Sheets.
