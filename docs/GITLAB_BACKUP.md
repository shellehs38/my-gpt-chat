# GitHub → GitLab: правило резервирования

GitHub — основное место работы. Ветки/коммиты/теги сохраняются в закрытый GitLab svoi-ludi-group. Нельзя удалять GitHub, принудительно перезаписывать рабочие ветки другой площадки или менять production в рамках резервирования.

Расписание подготовлено: каждый понедельник 01:17 UTC / 09:17 Иркутск, также workflow_dispatch. Сохранение в backups/<UTC-время>-<run-id>-<attempt>/; старые снимки не удаляются. Каждый запуск сверяет SHA и проверяет клонирование из GitLab через git fsck.

## Активация — пока НЕ выполнена
1. Создать отдельный SSH deploy key с can_push только для соответствующего закрытого проекта GitLab.
2. Сохранить приватный ключ в GitHub Actions secret GITLAB_BACKUP_SSH_KEY только этого репозитория. В Git и переписку секрет не помещать.
3. Принять PR в default branch и вручную запустить Weekly GitLab backup.
4. Проверить зелёный запуск, summary и снимок в GitLab. Наличие YAML само по себе не означает работающее резервирование.

На 11.11.2026 текущая GitHub-интеграция возвращает 403 для управления Actions secrets и deploy keys. Расписание не активировано. Пробный сетевой запуск не выполнен. Разовое копирование по HTTPS всех текущих веток и тегов проверено отдельно.

GitHub Actions может задерживать расписание и не работает при блокировке аккаунта. В этом случае сохранённые GitLab-копии остаются. Уведомления о сбоях зависят от настройки Actions Notifications владельцем.

Не входят: Git LFS объекты, wiki, issues/PR, вложения, базы, ключи, переменные сервисов, чаты. Их нельзя считать скопированными по наличию Git-снимка. Автоматическое удаление старых копий не включено.

Host key GitLab закреплён из https://gitlab.com/gitlab-org/gitlab/-/raw/master/doc/user/gitlab_com/_index.md; ротация требует повторной проверки официального источника.

Дополнение: сохраняются также доступные refs/pull/* в backups/<снимок>/github-pull/*. Созданы отдельные GitLab deploy keys can_push для каждого проекта; приватные части пока НЕ установлены в GitHub Secrets. Разовый расширенный экспорт metadata и журналов хранится в закрытом project-materials/github-exports/2026-11-11; его еженедельная автоматизация ещё не включена.

## Расширенный экспорт

Расширение сохраняет доступные issues, PR, комментарии, ревью, labels, milestones, релизы и вложения релизов, environments, workflows, списки запусков/артефактов, доступные журналы и артефакты. Данные располагаются в отдельной ветке backups/<снимок>/metadata. COVERAGE.json перечисляет выгруженное и недоступное; FILES.json содержит контрольные суммы. Бинарные файлы разбиваются на части по 40 MiB, их сборка и проверка описаны в README снимка. После копирования каждый файл проверяется чтением из восстановленного GitLab-клона.

Secrets values, wiki, Git LFS objects, вложения обсуждений, Projects boards и webhook configuration не входят в это расширение. Список покрываемых данных не равен «всем данным компании». Невыгруженные обязательные обсуждения/PR делают запуск неуспешным после сохранения доступных данных. Для необязательных/истёкших ресурсов ошибки записываются в COVERAGE.json. Поиск известных шаблонов ключей не гарантирует обнаружение всех возможных секретов; GitLab остаётся закрытым.
