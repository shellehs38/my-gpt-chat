# Codex CLI → FreeLLMAPI: отдельный профиль без смены штатной модели

Дата подготовки: 2026-11-05. **Статус: конфигурация в GitHub подготовлена; установка на компьютере владельца и сквозной Codex-тест НЕ выполнены.**

## Что работает и что не работает

- FreeLLMAPI развёрнут на Railway: https://freellmapi-production-3129.up.railway.app . Он принимает OpenAI-совместимый `POST /v1/responses`, используемый Codex CLI. Для тестов в панели Google AI Studio и Groq отмечены Healthy; выполнены примеры запросов Gemini/Groq.
- Реальные запросы Codex с вызовом инструментов, SSE и восстановлением истории через этот шлюз **пока не проверены**. Наличие `/v1/responses` недостаточно для доказательства совместимости всего Codex.
- **Настройки внешнего провайдера в `.codex/config.toml` репозитория нынешний Codex игнорирует.** `model_providers` и `model_provider` задаются в пользовательском `~/.codex/config.toml`, а профиль — отдельным `~/.codex/svoi-freellmapi.config.toml` с запуском `codex --profile svoi-freellmapi`.
- **ChatGPT Work и облачный Codex не начинают использовать FreeLLMAPI из-за этих файлов.** Work может читать проектные инструкции из GitHub при наличии разрешённого подключения; его внутренний провайдер этим способом не переключается. Штатный Codex без указанного профиля не меняется.

## Почему не запускаем автоматически `npx freellmapi setup-codex`

Проверен upstream `cli/src/tools.ts` на 2026-11-05: генератор по-прежнему записывает `[profiles.NAME]` прямо в `~/.codex/config.toml` и считает, что отдельные файлы профилей не читаются. Актуальная официальная документация Codex утверждает обратное: с Codex >=0.134.0 используются **`~/.codex/NAME.config.toml`**; старые `[profiles.*]` игнорируются. Поэтому до исправления upstream установщик **не применять**, чтобы не повредить действующую конфигурацию. Использовать приведённые ниже два проверяемых шаблона вручную.

Источник upstream: https://github.com/tashfeenahmed/freellmapi/blob/main/cli/src/tools.ts
Документация Codex: https://learn.chatgpt.com/docs/config-file/config-advanced

## Не путать ключи

Нужен **единый API-ключ самого шлюза FreeLLMAPI** (раздел `Ключи → Единый ключ API`), а **не** ключ Google AI Studio, Groq, пароль панели управления или setup code. В GitHub и чат не передавать ни один из них.

## Установка на Windows / Legion Go (только в локальном Codex CLI)

1. Установить локальный [Codex CLI](https://github.com/openai/codex) по актуальной инструкции. Убедиться, что `codex --version` работает в PowerShell. Пользователю необходимо иметь доступ к командной строке **своего компьютера**; iPhone и ChatGPT Work Cloud не выполняют этот шаг автоматически.
2. Сохранить существующий `$HOME\.codex\config.toml` в резервную копию. Не заменять текущий файл целиком, чтобы не ломать встроенные провайдеры и другие настройки.
3. Открыть `$HOME\.codex\config.toml` и **добавить в конец** только секцию из [шаблона провайдера](../tools/codex/freellmapi-provider.config.toml.example). Если секция `[model_providers.svoi_freellmapi]` уже есть, не дублировать её; сверить значения.
4. Создать **отдельный** файл `$HOME\.codex\svoi-freellmapi.config.toml`, скопировав [шаблон профиля](../tools/codex/svoi-freellmapi.config.toml.example). Не добавлять в пользовательский базовый файл `model_provider = ...` верхнего уровня: штатный режим должен остаться неизменённым.
5. Перейти в [панель FreeLLMAPI](https://freellmapi-production-3129.up.railway.app) и скопировать **единый ключ шлюза**. Хранить в защищённом хранилище паролей; не вписывать в TOML, скрипты, историю PowerShell, issue или скриншоты. Перед запуском из PowerShell без отражения символов:
   ```powershell
   $secure = Read-Host "Вставьте единый API-ключ FreeLLMAPI" -AsSecureString
   $env:SVOI_FREELLMAPI_UNIFIED_KEY = [System.Net.NetworkCredential]::new("", $secure).Password
   ```
6. На корне клона репозитория выполнить **независимый диагностический тест шлюза**:
   ```powershell
   node scripts/check-codex-freellmapi.mjs
   ```
   Успех требует `GET /v1/models` и **потоковый** `POST /v1/responses` с событием `response.completed`. Запрос тестовый, без клиентских данных. При 401 — неверный/отсутствующий *единый* ключ, не ключ провайдера; 429/503 — временная квота/перегрузка, 404 — неверный endpoint, 200 без `response.completed` — несовместимость потока.
7. Только после успешного теста выполнить:
   ```powershell
   codex --profile svoi-freellmapi
   ```
   В Codex предложить безопасную задачу на тестовых данных: «Прочитай AGENTS.md, перечисли правила работы и создай план проверки тестовой функции; никаких изменений не выполняй». Далее отдельно проверить вызов локального инструмента/чтение файла и сохранение контекста в нескольких запросах.
8. После завершения закрыть экземпляр Codex и удалить переменную из **текущей** сессии PowerShell:
   ```powershell
   Remove-Item Env:\SVOI_FREELLMAPI_UNIFIED_KEY -ErrorAction SilentlyContinue
   ```
   Обычный Codex запускается командой `codex` без профиля, как раньше.

### Linux / macOS

Те же файлы в `~/.codex/`. Экспортировать ключ в переменную окружения безопасным способом вашего shell без записи в историю команд, проверить `node scripts/check-codex-freellmapi.mjs`, затем `codex --profile svoi-freellmapi`. Удалить переменную после сеанса.

## Контроль результата и допуск к задачам компании

1. Тест `/v1/responses` с SSE, затем Codex CLI с чтением `AGENTS.md`, обработкой tool calls и двумя последовательными запросами; зафиксировать **фактическую** модель/провайдера и метрики. При отсутствии теста статус = «не подключено».
2. Отдельно проверить качество кода и стабильность fallback Gemini/Groq при 429/5xx, не имитируя реальный отказ путём повреждения действующих ключей.
3. Соглашения пользователей и тарифов провайдеров должны разрешать такой сценарий. Внешним моделям не передавать закрытый код, персональные и клиентские данные, реальные сметы или документы без отдельной проверки условий и разрешения владельца. Upstream FreeLLMAPI позиционируется для личных экспериментов, не как гарантированный корпоративный production backend.
4. Только после теста обновить [журнал интеграций](AI_INTEGRATION_STATUS_20261105.md), `AGENTS.md` и PR с конкретными доказательствами. Рабочий Vercel Production не переключать.

## Почему не одна кнопка в GitHub

GitHub хранит общие инструкции и файлы, а не настройки локального клиента, секреты или переключатель моделей самого ChatGPT/Work. Для Codex CLI этот профиль поддерживается **только при запуске с `--profile` на машине, где настроены пользовательские файлы и переменная ключа**. Для Work из ChatGPT нет подтверждённого способа выбрать внешние Gemini/Groq как её собственную модель.
