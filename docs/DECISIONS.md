# Журнал решений проекта

Новые решения добавлять сверху с датой, контекстом и статусом.

## 2026-10-12 — GitHub как источник истины

**Решение:** вести в GitHub код, проектную память, журнал изменений, решения, дорожную карту и проверенную документацию.

**Правило:** значимые итоги разговоров о проекте фиксировать в документации. Не полагаться только на историю чата.

**Статус:** принято.

## 2026-10-12 — Безопасное внедрение

**Решение:** разработку вести в ветке `feature/construction-assistant-v1` и через draft PR №1.

**Правило:** не объединять в `main` и не менять production до успешной проверки и отдельного подтверждения пользователя.

**Статус:** принято.

## 2026-10-12 — Отделить документацию проекта от истории чатов

**Решение:** проектные обсуждения хранить как сводки и решения в GitHub. Полную историю разговоров пользователей в работающем приложении реализовывать отдельно, с базой данных и контролем доступа.

**Причина:** GitHub — система контроля версий, а не подходящая по умолчанию база для пользовательских сообщений; секреты и персональные данные нельзя помещать в репозиторий.

**Статус:** принято как архитектурное направление; хранилище чатов ещё не реализовано.
