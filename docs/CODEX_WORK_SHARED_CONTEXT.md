# Единая проектная память для Codex и ChatGPT Work

**Проект:** ООО «СВОИ ЛЮДИ» — ИИ-помощник и строительные процессы.  
**Последнее обновление:** 2026-11-05.  
**Источник истины:** проверенный код, текущие настройки и тесты, а не пересказ предыдущих ответов.

## Как читать эту память

1. `AGENTS.md` — обязательные инструкции при работе Codex в этом репозитории. Начинай с него.
2. Этот файл — краткий вход для **Codex, Work и других агентов с разрешённым доступом к GitHub**.
3. `docs/AI_INTEGRATION_STATUS_20261105.md` — журнал состояния провайдеров, подтверждений и следующих проверок. Обновляй при изменениях.
4. `docs/MODEL_ROUTING_FREELLMAPI.md` и `docs/OMNIROUTE_RAILWAY_AUDIT_20261104.md` — технические границы интеграции.
5. `docs/CODEBASE_MEMORY_ADR.md` и `docs/CODEBASE_MEMORY.md` — индекс и правила памяти кодовой базы.
6. `BRAND_LOGO_RULES.md` и `DOCUMENT_BRANDING.md` — обязательная идентичность документов, смет и визуалов.

## Контекст бизнеса

Компания работает с частными заказчиками в Иркутске: фасады (текущий приоритет), бетонные работы, отмостки, заборы, ливневая канализация. Развиваются учёт клиентов/объектов/расходов/смет, документация и автоматизация. Ответы пользователю — на русском, с понятными шагами и прямыми проверенными ссылками. По строительным вопросам применять формат «вывод → шаги → риски → чек-лист». Не выдумывать нормы, цены или несущие расчёты: материалы и работу в сметах разделять, СП/ГОСТ и конструктивную часть проверять с профильным специалистом.

Для клиентских документов: строго три утверждённых PNG, полупрозрачный водяной знак «СВОИ ЛЮДИ», фактическая проверка экспорта. Не добавлять автоматически старую наценку 40%; вопрос зарплаты руководителя и метод калькуляции согласовать для конкретного расчёта, не смешивать наценку с зарплатой.

## Границы контекста и моделей

- **Codex:** при работе с клонированным репозиторием читает `AGENTS.md` до задачи. Документы GitHub доступны по факту доступа/чтения. Коммит не загружает контекст магически в каждую модель.
- **ChatGPT Work:** при наличии разрешённого подключения GitHub может открыть эти файлы по запросу. Work не обязан автоматически читать этот документ при каждом новом чате.
- **FreeLLMAPI:** отдельный Railway-сервис, маршрутизирует запросы, которые **явно отправлены через его API**.
- **OmniRoute:** другой Railway-сервис; живой контейнер ≠ доказанная маршрутизация или работоспособность API inference.
- **Codex / ChatGPT Work:** установка FreeLLMAPI или запись URL в GitHub **не меняют** внутреннюю модель или лимиты продукта. Возможность отдельного CLI-шлюза оценивается только после подтверждения поддерживаемого протокола, локальных прав и безопасного способа хранения ключа.
- Память GitHub — версии правил и решений, **не** полный архив ChatGPT/клиентских данных. При переключении внешних моделей передавать только разрешённый контекст через серверную логику сайта.

## Сохранение уроков (требование владельца)

После задачи, которая меняет систему:
1. Проверить факты кодом, API/логами и тестом. Отделить **проверено** от **со слов/планируется**.
2. Обновить соответствующую документацию и `docs/AI_INTEGRATION_STATUS_20261105.md` (или последующий журнал со ссылкой отсюда).
3. Если обнаружено новое долговременное правило, кратко обновить корневой `AGENTS.md` и `docs/CODEBASE_MEMORY_ADR.md`; не раздувать `AGENTS.md` деталями дневника.
4. Для изменённого кода запускать `npm run memory:index`, `npm run memory:check`, `npm run typecheck`, `npm test`, `npm run build` по применимости. При невозможности — явно записать «не выполнено».
5. Работать через отдельную ветку и PR; **не трогать Vercel Production, Railway Variables, ключи и платные тарифы без отдельного разрешения**. Приложить ссылку PR, результаты проверок и ссылку актуального сайта после реального выпуска.

Прочитай `AGENTS.md`, `docs/CODEX_WORK_SHARED_CONTEXT.md`, `docs/AI_INTEGRATION_STATUS_20261105.md`, затем только относящиеся к задаче исходники. Перед изменениями покажи план, сохрани уроки в отдельной ветке/PR и не меняй Production без разрешения».

## Что НЕ хранить в GitHub

Пароли, setup codes, токены и API-ключи (включая скриншоты), ключи Google service account, персональные данные клиентов, приватные диалоги и полный контекст пользователя без осознанной минимизации/разрешения. На GitHub публикуются имена переменных и инструкции, но не значения секретов.
