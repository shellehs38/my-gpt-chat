# Память кода строительного помощника

В проект подключён [Codebase Memory MCP](https://github.com/DeusData/codebase-memory-mcp/releases/tag/v0.12.1), закреплённый на версии **0.12.1**. Он индексирует функции, импорты и связи кода, выполняет поиск и хранит архитектурные решения между сессиями. Это инструмент разработки; рабочие клиенты и расходы остаются в Google Таблице.

## Общая память сайта и ChatGPT

При `npm run build` автоматически выполняется `memory:export`: закреплённый нативный Codebase Memory индексирует текущие исходники, синхронизирует ADR и экспортирует публичные правила и расположения символов. Ошибка индекса останавливает сборку. Снимок включён в серверные функции Next.js; сам бинарник в функции не упаковывается. Никаких новых секретов или отдельного платного хостинга для этого адаптера не нужно.

GPT-чат сайта добавляет память в серверный контекст каждого обращения. MCP endpoint **https://my-gpt-chat-theta.vercel.app/api/mcp** предоставляет тот же снимок плагину ChatGPT через стандартный Streamable HTTP. Доступны четыре инструмента чтения: `get_project_memory`, `get_memory_status`, `search_codebase`, `get_file_outline`. Это адаптер опубликованного снимка, не все 17 инструментов нативного движка: произвольный Cypher, команды, изменения ADR, запись клиентов и переписки удалённо не выполняются.

Endpoint публичный: он содержит только сведения из уже публичного GitHub-репозитория. Env, исходный текст файлов, пользовательские ADR вне управляемого списка, данные клиентов и история разговоров не экспортируются. `revision`, `fingerprint` и `generatedAt` показывают, какую версию читает клиент. Новое правило меняйте в `docs/CODEBASE_MEMORY_ADR.md` и публикуйте сборку; сообщение в чате само не переписывает этот файл.

Подключение прописано в существующем приватном плагине «СВОИ ЛЮДИ — Стройпомощник». Конфигурация и загрузка навыка сами не регистрируют инструменты в ChatGPT: новый разговор тоже не гарантирует активацию MCP. Проверяйте фактическое наличие `get_memory_status` / `get_project_memory`.

В облачном режиме без инструментов хоста память можно реально прочитать тем же MCP-протоколом: `python scripts/read-project-memory.py`. Клиент выполняет initialize, согласует версию, читает tools/list и вызывает get_project_memory; проверяет проект, отпечаток и правило логотипа. Используются стандартная библиотека Python, действующий proxy и CA trust, без SDK и ключей. Копия клиента включена в навык project-memory; помощник должен выполнить его, а затем сообщить факты из результата. Такой запуск не регистрирует новые инструменты в палитре ChatGPT. При отсутствии среды исполнения или при сетевой ошибке нужно назвать конкретный барьер, а не отправлять пользователя по кругу открывать новые чаты.

Для нативных инструментов ChatGPT используется отдельный этап подключения в веб-интерфейсе: [Plugins](https://chatgpt.com/plugins) → плюс → Add custom MCP server → указанный endpoint → без аутентификации → проверка списка инструментов. Доступность зависит от тарифного плана и политики аккаунта. В мобильном приложении этот этап подключения не поддерживается. [Официальная инструкция](https://developers.openai.com/plugins/deploy/connect-chatgpt). Сервер и клиент из облачной среды проверяются отдельно от завершения этой операции в интерфейсе аккаунта.

## Запуск

Для проверенного проектного запуска нужны Linux или macOS, Node.js >=22, `curl` и `tar`.

```sh
npm run memory:install
npm run memory:index
npm run memory:check
```

Установщик загружает конкретный релиз, проверяет SHA-256 архива и исполняемого файла по `tools/codebase-memory.lock.json` и извлекает бинарник и сведения о лицензиях. Он не запускает внешний install.sh, не меняет глобальные инструкции, hooks или другие MCP-клиенты. На macOS/arm64 предусмотрены закреплённые релизные файлы; практический прогон этого изменения выполнен на Linux x64. Для Windows используйте официальный установщик и настройте клиент на его бинарник.

## Codex и другие клиенты

- `.codex/config.toml` — проектная конфигурация Codex для **доверенного checkout**. После установки бинарника запустите Codex из корня checkout и откройте новую сессию. Если клиент запрашивает доверие к проекту, его подтверждает владелец в клиенте; репозиторий не меняет эту настройку за него.
- `.mcp.json` — стандартная конфигурация MCP-клиентов, которые поддерживают этот файл. Запускайте клиент из корня checkout.
- Для Codex CLI, который использует только пользовательскую конфигурацию, выполните из корня репозитория:

```sh
codex mcp add codebase_memory -- node "$(pwd)/scripts/codebase-memory.mjs" serve
codex mcp get codebase_memory --json
```

`mcp get` подтверждает регистрацию, но не выполнение инструментов. Проверка полного JSON-RPC запуска, обнаружения инструментов, индекса и запросов выполняется через `memory:check`. Новые MCP-инструменты могут потребовать новую сессию Codex; конфигурация в GitHub не делает их автоматически доступными каждому чату ChatGPT или браузерному сайту.

## Что сохраняется

- Исходники и постоянные решения: GitHub, `AGENTS.md`, `DOCUMENT_BRANDING.md`, `docs/CODEBASE_MEMORY_ADR.md`.
- При `memory:index` управляемые секции ADR переносятся в память индекса. Другие секции, добавленные разработчиком, сохраняются.
- Локальная база: стандартный пользовательский cache Codebase Memory или выбранный `CBM_CACHE_DIR`. Она сохраняется после завершения процесса.
- `.codebase-memory/graph.db.zst` — восстанавливаемый сжатый снимок после `memory:index`. Он исключён из Git, чтобы частые обновления не раздували историю. GitHub Actions сохраняет снимок и отчёт как артефакт проверки с ограниченным сроком хранения.
- Бинарник хранится в `.local/codebase-memory/`, также вне Git. В npm-зависимости приложения он не добавлен, на Vercel при сборке сайта не устанавливается.

## Работа с индексом

Обновляйте индекс после изменений. При обычном MCP-сеансе upstream может следить за git-проектом; CLI-сеанс такого постоянного слежения не обещает. Используйте `index_status` и `check_index_coverage`, а выводы подтверждайте исходниками и тестами. Отсутствие ребра в графе не доказывает отсутствие зависимости.

```sh
node scripts/codebase-memory.mjs cli list_projects --format json
node scripts/codebase-memory.mjs cli search_graph --project svoi-lyudi-builder --name-pattern runLedgerCommand --format json
node scripts/codebase-memory.mjs cli manage_adr --project svoi-lyudi-builder --mode get --format json
```

`.cbmignore` исключает env-файлы, ключи, конфигурацию клиента и сгенерированные каталоги. `CBM_ALLOWED_ROOT` ограничивает индексируемый путь текущим checkout. Общие ограничения доступа Codebase Memory и cache остаются в силе. Все процессы одного пользователя должны использовать совместимые сборки и один канонический cache; при конфликте версий завершите прежний собственный MCP-сеанс и переподключитесь, не удаляя его базу.

## GitHub

Workflow **Codebase Memory** запускается на `push`, `pull_request` и вручную. Он устанавливает закреплённый бинарник, проверяет MCP на текущем коде и сохраняет JSON-отчёт, граф и метаданные снимка. Каталог пользовательского cache и бинарники в артефакт не включаются. Для доступа к GitHub, OpenAI или Google ключи не нужны: индекс строится по checkout без серверных секретов.

Проверка не меняет сайт, не записывает клиентов или расходы и не вызывает модель. Работа сайта и настройка Google-подключения проверяются отдельно существующими тестами.
