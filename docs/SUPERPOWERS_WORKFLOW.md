## Назначение и состояние

Superpowers — набор навыков организации работы агента, а не модель, API-провайдер, память или маршрутизатор. Источник: https://github.com/obra/superpowers.
В ChatGPT каталог подтвердил installed=true и status=ENABLED. Дополнительная проверка текущей Cloud-среды Codex выполнена 19.11.2026: локальный Codex CLI 0.167.0-alpha.4, Superpowers 7.0.2 installed/enabled; отдельный процесс app-server обнаружил 9 из 9 обязательных навыков через skills/list. Файлы навыков читаются и совпадают с официальным upstream commit 22f0b463e7a5e579904dd6211a520321035526f7. Подробности, команды и границы: [INTEGRATION_AUDIT_20261119.md](INTEGRATION_AUDIT_20261119.md). Другие компьютеры, отдельные Codex App/Work и будущие окружения этой проверкой не охвачены. Наличие документации не подтверждает их установку. Не дублировать установленный плагин и не переносить навыки в Production автоматически.

## Обязательное применение

| Сценарий | Навыки / действия |
| --- | --- |
| Начало технической задачи | using-superpowers; прочитать AGENTS.md, определить применимые навыки, контекст и разрешения |
| Новая функция или архитектура | brainstorming; согласовать существенные требования, затем writing-plans |
| Реализация плана | using-git-worktrees при необходимости изоляции; executing-plans или subagent-driven-development при доступности соответствующих возможностей |
| Исправление ошибки | systematic-debugging: воспроизведение, поиск первопричины, проверка гипотез; test-driven-development для изменений кода |
| Новая функциональность | test-driven-development: тест до реализации, подтверждение падения теста по ожидаемой причине, минимальная реализация, повторный тест |
| Независимые задачи | dispatching-parallel-agents только при реальной доступности агентов и отсутствии зависимостей |
| Завершение и ревью | requesting-code-review, receiving-code-review по ситуации; verification-before-completion: свежие проверки и фактические результаты |
| Подготовка к объединению ветки | finishing-a-development-branch; соблюдать запрет автоматического слияния и правила владельца |

## Контроль качества и расходов

1. Определить цель, критерии приёмки, затронутые файлы и риски; прочитать исходники, использовать Codebase Memory при доступности.
2. Для сложной задачи составить проверяемый план; простую правку выполнить без искусственного многоэтапного процесса. Не требовать TDD от текста, где нет исполняемого кода: проверить содержание, ссылки и сохранность прежних правил.
3. Использовать отдельную ветку и ограниченный diff. Для внешних операций применять Composio согласно AGENTS.md; не дублировать интеграции и не обходить OAuth-ограничения.
4. Для кода выполнить релевантные тесты, типизацию, сборку и ревью в доступной среде. Указывать конкретные команды, статусы и идентификаторы результатов. Непроведённую проверку обозначать явно.
5. Фиксировать подтверждённые результаты, ограничения, оставшиеся действия, ссылку на PR; не хранить ключи, клиентские данные, письма и частные документы в репозитории.
6. Не менять Production, тарификацию, ключи, действующий учёт и не объединять PR без отдельного согласования. Если навыки отсутствуют, применить процесс вручную и зафиксировать ограничение. Не обещать устранение лимитов или гарантированную экономию токенов.

## Подключение в отдельной среде Codex

Официальный README описывает установку через каталог плагинов Codex App (Plugins → Superpowers → установка) и через /plugins в Codex CLI. Использовать только поддерживаемый в данной среде способ, проверить актуальную документацию и реальные разрешения. Не считать установку ChatGPT доказательством подключения Codex/Work. Для проверки загрузить using-superpowers и один применимый навык в конкретном сеансе, выполнить небольшую безопасную задачу и сохранить доказательство в отдельном PR.
