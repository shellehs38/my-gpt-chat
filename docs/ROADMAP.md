# Дорожная карта строительного помощника

Статусы: `Запланировано`, `В работе`, `Ожидает проверки`, `Готово`.

## Этап 1. Основа приложения
- [ ] Проверить сборки Vercel для ветки `feature/construction-assistant-v1`.
- [ ] Проверить чат на телефоне и форматирование Markdown.
- [ ] Исправить ошибки и подтвердить работу до слияния.

## Этап 2. Расчётные инструменты
- [ ] Добавить отдельные проверяемые функции для площадей, объёмов, количества материалов и итогов сметы.
- [ ] Показывать формулы, единицы измерения, исходные данные и допущения.
- [ ] Разделить материалы и работы; поддержать цены пользователя и расчёт себестоимости/прибыли.
- [ ] Добавить тесты расчётов и проверки граничных случаев.

## Этап 3. База знаний
- [ ] Выбрать способ хранения документов и поиска по ним.
- [ ] Добавить загрузку и поиск по проверенным нормативам, инструкциям производителей, внутренним документам и прайсам.
- [ ] Указывать источник, дату и область применимости; не выдавать непроверенное значение за норматив.
- [ ] Не загружать клиентские документы с персональными данными без необходимости и правил доступа.

## Этап 4. Рабочие документы и проекты
- [ ] Генерировать сметы, коммерческие предложения, договоры и акты по шаблонам.
- [ ] Добавить сохранение проектов, версий смет и принятых решений.
- [ ] Добавить экспорт документов и журнал изменений.

## Этап 5. История чатов и база данных приложения
- [ ] Определить модель данных: пользователи, чаты, сообщения, проекты, файлы и версии документов.
- [ ] Выбрать защищённую БД и настроить авторизацию и права доступа.
- [ ] Сохранять историю разговоров в приложении только после реализации контроля доступа и правил хранения.
- [ ] Добавить экспорт и удаление данных.

## Этап 6. Бизнес-инструменты
- [ ] Учёт заявок, клиентов и объектов.
- [ ] Воронка продаж, напоминания и контроль следующих действий.
- [ ] Анализ расходов, себестоимости, прибыли и закупок.

## Правило приоритета

Сначала добиться стабильной сборки и безопасного первого этапа, затем добавлять функции небольшими проверяемыми изменениями. Не внедрять все подсистемы одним большим изменением.
